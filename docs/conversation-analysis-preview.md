# 对话分析预览

此分支在原有悬浮弹框中提供三项能力，沿用原来的任务、历史、统计和账户标签：

- **需求提炼**：每条真实用户发言（含同轮补充）触发一次分析，同时区分会话整体目标与本轮具体目标，仅供展示和核对。
- **回复摘要**：主 AI 的最终回复出现后生成简短摘要，原文可以展开。
- **技能提炼**：用户点击按钮后，分析会话开始到所选轮次的内容，生成可编辑、可导出的 `SKILL.md` 草稿。

它不向主 AI 反馈分析结果，也不安装生成的技能。任务详情按“会话目标 → 本轮目标 → 本轮结果”排列，技能草稿在同一弹框内展开。分析结果独立读取，不改写主 AI 的目标发布记录。

## 启动

需要 macOS、Xcode、Python 3、支持本分支所用 `codex exec` 参数的 Codex CLI，以及现有 Codex 登录。首次运行或 Swift 源码变化时会构建本分支的原生程序。

从此 worktree 执行，明确指定一个 Desktop 会话文件及其 `session_meta.payload.id`：

```bash
python3 scripts/preview-analysis.py start \
  --state-dir /tmp/flowpilot-my-preview \
  --transcript /absolute/path/to/rollout.jsonl \
  --session-id SESSION_ID \
  --model gpt-5.6-luna \
  --auth-home "$HOME/.codex"
```

`--state-dir` 应为空目录或本预览已配置的目录。后续可以只传同一个目录继续：

```bash
python3 scripts/preview-analysis.py start --state-dir /tmp/flowpilot-my-preview
python3 scripts/preview-analysis.py status --state-dir /tmp/flowpilot-my-preview
python3 scripts/preview-analysis.py stop --state-dir /tmp/flowpilot-my-preview
```

点击原有收起按钮会回到悬浮气泡，后台分析继续。通过气泡右键菜单退出，或使用上述 stop 命令，可以停止预览和后台分析。分析结果保留在私有状态目录；退出时删除临时登录凭据副本。启动器通过本地验证口令控制自身进程，不会按记录中的旧 PID 杀进程。

## 任务页层级

- **会话目标**：截至所选轮次，用户最终想达成什么。一句话，最多 48 字。
- **本轮目标**：本轮新增或修正的具体任务。一句话，最多 40 字。
- **本轮结果**：本轮实际结果和关键未完成项。一至两句，最多 80 字；未回复时显示“等待本轮回复”。
- **需求详情**：默认收起，参考用户提供的 `true-need`，展开为“真正需求／更好说法／下一步”；证据、矛盾、缺口仅在有用时出现。
- **回复原文、用量与执行详情**：默认收起。技能提炼仍是手动入口。

旧版混合需求不会被当作本轮目标。点击“更新提炼”可为所选旧轮次生成新格式，历史不会自动批量重算。长度由生成结果校验，不通过截断冒充提炼。

## 试用方法

1. 默认打开最新轮次；使用弹框底部“上一轮／下一轮”或原有“历史／切换”入口选择轮次，再点“分析此轮”补充历史需求和摘要。
2. 在原对话继续发言，查看新需求。浏览历史时不会自动跳走，任务页会标明“正在查看历史”，点击“返回当前任务”恢复跟随指定会话的最新轮次。其他会话的完成记录不会替换当前分析任务。
3. 点击“提炼技能”，等待草稿，编辑后导出。尚未结束的轮次也可以作为截止位置；模型会说明缺少的验证证据。
4. 隐私开关隐藏原文、派生文本，并禁止分析、导出等操作。**它只隐藏界面，不暂停后台分析**；需要停止时从气泡右键菜单退出预览。

## 初版边界

- `goal.internal_context` 自动继续消息及没有真实用户发言的对应回复不会计入用户轮次。升级时自动清理已导入的这些消息，保留不受影响的结果；受污染的提炼失效，历史按需重新提炼，不批量补跑。
- 原弹框沿用当前 `CODEX_HOME`（默认 `~/.codex`）的历史、统计和账户数据，并监听原遥测更新。分析队列、模型运行目录和构建产物仍独立保存；未完成轮次缺少遥测时显示未记录。

- 仅验证了带稳定消息 ID、轮次 ID 和父会话标识的 Codex Desktop transcript。其他来源会显示错误，不猜测归属。
- 初次启动只自动分析最新用户消息及最新最终回复，历史内容用作上下文；不会批量补跑历史。没有最终回复就不会伪造摘要。
- 模型上下文上限为 32,000 字符。需求提炼优先完整保留截至所选轮次的全部用户发言，再补入近期 AI 回复，避免中途修正的目标被丢弃；用户发言本身超限时明确报错，不生成部分需求。摘要只使用本轮完整最终回复，超限时显示“回复超出摘要上限，请查看原文”，不调用模型、不静默截断。技能和可选 AI 上下文被截断时，界面显示输入不完整提示。分析不读取工具执行记录，技能里的执行证据仍需人工核对。
- 默认每个任务最多尝试两次，单次超时 90 秒；失败后由用户重试。普通重复扫描不会重复入队。进程在外部模型调用与结果保存之间崩溃时，恢复可能重新调用，不能保证服务端恰好执行一次。
- 额外分析消耗同一 Codex 账户额度。后台记录尝试调用次数，原弹框的 Token 与额度统计仍来自主任务遥测；不会改写原来的 telemetry/goal/publication。
- 不运行安装脚本，不替换已安装应用、hooks 或全局配置。启动、停止和构建均在独立路径下进行。
