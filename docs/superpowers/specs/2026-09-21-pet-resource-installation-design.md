# codex-flow 宠物安装：简版方案

状态：已在 `codex/petdex-pets` 分支实现，使用说明见 [宠物安装指南](../../pets.md)。

## 用户只走三步

1. 打开 [Petdex](https://petdex.dev)，挑一个宠物，复制名称。
2. 执行安装命令。
3. 安装成功后，FlowPilot 悬浮按钮换成这个宠物。

```bash
codex-flow pets install boba
```

命令负责查找资源、下载 `pet.json` 和精灵图、保存到本地，然后通知浮窗加载。用户不需要安装 Petdex 客户端或 Node。

浮窗没有运行时，保存选择，下次启动生效。首版显示只支持已有的 macOS 浮窗。

## 其他宠物库怎么接

先支持本地导入，沿用同一个安装命令：

```bash
codex-flow pets install ./my-pet.zip
codex-flow pets install ./my-pet/
```

第一版接受 Petdex/Codex 风格的 `pet.json` 加 PNG/WebP 精灵图，支持 v1、v2。同格式的其他库直接可用。

GIF、Shimeji 等不同格式，需要针对格式补一个读取器。等选定具体资源库再加，不承诺现在能导入任意动画文件。

以后需要从其他网站直接下载时，增加来源前缀即可，命令形式预留为 `codex-flow pets install 来源:名称`。裸名称始终指向 Petdex。

## 首版只保留四个操作

| 操作 | 命令 |
| --- | --- |
| 安装并启用 | `codex-flow pets install boba` |
| 查看已安装宠物 | `codex-flow pets list` |
| 切换宠物 | `codex-flow pets use boba` |
| 恢复当前默认形象 | `codex-flow pets use default` |

本地导入完成后打印可用于切换的 ID；名称冲突时要求换名。重复安装已有宠物直接启用，不自动覆盖文件。

资源浏览继续用原网站。首版不做内置商城、搜索页、来源管理或自动更新。

## 实现分成三小块

- **下载**：Python 读取 Petdex 公开目录，下载资源；本地文件走复制或解压。
- **保存**：统一放在 `~/.codex/codex-flow/pets/`（跟随 `CODEX_HOME`），另外记录当前选择。下载失败保留旧宠物，应用升级保留资源；卸载脚本也需明确保留宠物目录。
- **显示**：Swift 按 Petdex 标准播放九种动画，由真实任务事件和鼠标交互切换状态。点击、拖动和展开维持现有行为。

两种安装入口共用文件检查：拒绝越界路径、过大或损坏的图片；完整验证后才替换当前形象。只安装数据，不执行资源包里的脚本。加载失败恢复默认形象，遵循系统“减少动态效果”。

## 首版完整支持 Petdex 的九种状态

状态名称、行顺序、有效帧数和帧时长以 [Petdex 动画表](https://github.com/crafter-station/petdex/blob/a1b229116968cbe9f3a9b2141634a9baa0819864/packages/petdex-desktop-native/src/sprite.zig) 为基线。下表的触发条件是 FlowPilot 的设计约定。

| 行 | 状态 | 有效帧数 | FlowPilot 何时播放 |
| --- | --- | --- | --- |
| 0 | `idle` 空闲 | 6 | 没有活动任务或短动作结束后回到空闲 |
| 1 | `running-right` 向右跑 | 8 | 用户向右拖动按钮时 |
| 2 | `running-left` 向左跑 | 8 | 用户向左拖动按钮时 |
| 3 | `waving` 挥手 | 4 | 鼠标进入，或新结果发布时播放一次 |
| 4 | `jumping` 跳跃 | 5 | 收到明确的任务成功事件时播放一次 |
| 5 | `failed` 失败 | 8 | 收到明确的任务失败事件时 |
| 6 | `waiting` 等待 | 6 | 任务需要用户输入、确认或授权时 |
| 7 | `running` 工作中 | 6 | 任务实际开始或恢复执行时 |
| 8 | `review` 审查 | 6 | 任务实际进入审查阶段时 |

v1 和 v2 都按前九行播放，v2 额外两行暂不使用。按每行有效帧数和原始帧时长播放，不把每行都当作八帧。

保持几条直观规则：

- 向左/向右跑只改变角色动作，窗口跟随用户拖动，不自动游走；停止拖动恢复当前任务状态。
- 等待或失败时不被悬停挥手覆盖。失败播放一次后保留代表帧，直到新一轮任务或切换关注任务；等待持续到用户响应、任务结束或实时状态过期。
- 同一轮的成功和结果发布合并为一次跳跃；只有完成结果、没有明确成功信号时挥手，不猜成功。历史刷新不重播。
- 短动作结束后回到真实任务状态；仅在没有活动任务时回到 idle。缺少某动作时退回 idle 或静态帧，任务文字仍显示真实状态。

**实时状态接入属于首版范围。** 当前浮窗主要接收已完成结果，需要补充开始/恢复、等待用户、进入审查、成功/失败这些事件。沿用本地 IPC，事件带会话与轮次身份、顺序和时间；不能根据计划配置或过往结果猜当前状态。暂时拿不到的事件显示为未知并用 idle 形象，不伪装成已接通。

浮窗显式跟随最近启动的任务，较早任务的迟到事件不覆盖它；同轮旧事件丢弃。非终态超过 120 秒没有新事件时清除临时状态，退回 idle 并标明状态不可用；历史详情仍按原来的已完成快照展示。动画状态不会修改结果发布和已读规则。

## 做到什么算完成

- 一条命令安装 Petdex 宠物，并在 macOS 浮窗中显示。
- 同格式的本地目录和 ZIP 可以安装。
- 可以列出、切换宠物和恢复默认形象。
- 下载或加载失败时，原来的按钮仍可用；断网不影响已安装宠物。
- PNG/WebP、v1/v2 均有实际播放验证；升级不丢宠物。
- 九种动画逐一验证：方向、行号、有效帧和时长正确；拖动、悬停、结束回退与减少动态效果正常。
- 开始、等待、恢复、审查、成功、失败都有真实事件接入验证；成功与结果发布不重复庆祝，旧事件和断连不会留下错误状态。仅手动切换动画不算完成实时接入。
